Method note (proof-scoping honesty): browser zoom shrinks the CSS layout viewport
while scaling content proportionally. Halving/quartering viewport width at normal
device-scale-factor approximates the CSS-pixel budget available at 200%/400% zoom
(the same equivalence WCAG 1.4.10's own guidance uses: 320 CSS px ~= 400% zoom at a
1280px baseline). This proves content-loss/overflow at the CSS-pixel-budget layer.
It does NOT prove Chrome's own pixel-for-pixel zoom rendering, browser-native
text-only zoom (Ctrl+Shift+= text scaling independent of layout), or every zoom
level in between 100-400%.
